# Film Remix

Пайплайн превращения полнометражного фильма в вертикальный ролик 45–70 c.
Эталон — композиция `JuniorKumite` («собеседование джуна» на кадрах «Кровавого
спорта»). Ключевая идея: **фильм сначала индексируется**, и дальше вся работа
идёт по индексу, а не просмотром.

## Два режима — выбери до начала

| | Реплики берём из фильма | Пишем свой диалог (смешной перевод) |
|---|---|---|
| Порядок | индекс → сценарий **из того, что сказано** | сценарий → **поиск кадров под текст** |
| Юмор | ограничен репликами фильма | полностью управляем |
| Что нужно | `quotes` (ASR) | `shots` (индекс действий) + `/voice-over` |
| Липсинк | совпадает | не совпадает (жанр это оправдывает) |

Второй режим сильнее: зрителю сразу понятен замысел. Первый — быстрее и звучит
органично. Спроси у пользователя, если не очевидно.

**Третий режим — закадровый монолог** (эталон `StethamTales`). Говорит не
персонаж, а рассказчик поверх чужих кадров: «сижу я в пабе, подваливают эти
двое». Липсинк не нужен вообще, поэтому кадры подбираются свободнее всего, а
пайплайн другой — `npm run vo` → **`npm run broll`** вместо `npm run cut`:
речь склеивается в одну дорожку (тишина по краям фраз срезается по пословным
таймингам), а планы привязываются к фразе и делят её длительность по весам.
Берите его, когда пользователь просит «рассказ», «историю от первого лица» или
требует, чтобы «шло без пауз»: в режиме «бит = реплика» пауза на склейке
неизбежна.

**Четвёртый режим — оригинальный звук** (эталон `ValleyAuction`). Этот режим
вырос в отдельный рецепт: если переозвучивать ничего не нужно, идите в
**`/series-cut`** — там выбор сцены по подборкам зрителей, трекинг лиц под
вертикаль, родной fps исходника и чек-лист приёмки. Ниже — краткая выжимка. Ничего не переозвучиваем: в ролике звучит дорожка
самого фильма, а караоке-субтитры строятся по её же словам. В `script.ts` у бита
нет `line`, стоит `subs: "source"` — `npm run cut` берёт слова из
`data/index/<фильм>/quotes.json`, сдвигает их к началу клипа и маскирует мат
(`maskProfanity`: «Ё*****-воробушки»), звук идёт на полной громкости. Шага
`npm run vo` в этом режиме нет вообще, длину бита задают только `start`/`end`.
Берите, когда юмор уже есть в самом материале, а зритель должен узнать сцену.

**Одна сцена против компиляции.** Для ленты шортсов сцена целиком обычно
сильнее нарезки «лучших моментов»: компиляция меняет контекст каждые несколько
секунд, и на каждой склейке часть зрителей уходит, а сцена с нарастанием и
панчем держит до конца. Практические следствия: хук — первой же репликой (не
установочным планом), панч — последним кадром, финальные плашки поверх панча не
ставим. Компонент развязан пропом `clipsFile`, поэтому
второй монтаж того же материала стоит одного `script.ts`.

## Пайплайн

```bash
npm run quotes -- <фильм>                      # все реплики с таймкодами (Groq, ~30 c на фильм)
npm run subs   -- <фильм>                      # то же из встроенных субтитров: бесплатно и точнее
npm run shots  -- <фильм> --from 26:00 --to 28:00 --ask "что искать"
npm run sheet  -- <фильм> --from 27:20 --to 27:40 --every 0.4   # кадры глазами
npm run vo     -- <Композиция>                 # озвучка, если свой диалог
npm run track  -- <Композиция>                 # трек лиц → траектория вертикального окна
npm run cut    -- <Композиция>                 # нарезка по script.ts (вертикаль вырезается здесь же)
npx remotion render <Композиция> out/<Композиция>/<имя>.mp4
```

Исходники в репозиторий не кладутся — только пути в `scripts/lib/films.ts`.
Индексы копятся в `data/index/<фильм>/` и переиспользуются между роликами.

## Три инструмента поиска и когда какой

1. **`quotes.txt`** (Groq whisper-large-v3-turbo) — грепается по ключевым словам.
   Ищи темами: «опыт», «готов», «правила», «деньги». Работает и во втором режиме:
   помогает понять, где какая сцена.
2. **`shots.txt`** (Gemini по видео) — что происходит в кадре: действие, кто,
   крупность, есть ли говорящий. Спрашивай конкретно («реакции шока крупным
   планом»), а не «опиши всё».
3. **Контактный лист** (`npm run sheet`) — десятки кадров в одной картинке с
   выжженным таймкодом, читается через `Read`. Это глаза агента: любой кадр,
   который реально попадёт в ролик, стоит увидеть до нарезки.

## Грабли (каждая стоила итерации)

- **Сначала проверь субтитры в контейнере, потом зови ASR.** `ffprobe` покажет
  дорожки; `npm run subs` соберёт из них тот же индекс бесплатно, точнее (имена
  собственные не искажены) и мимо почасового лимита Groq (ASPH 7200 c — два
  полных фильма подряд его выбирают, дальше ждать 40+ минут). Бонус: субтитры
  содержат надписи-локации («ГДЕ-ТО НА ПОЛОЙ ЗЕМЛЕ»), которых ASR не слышит, —
  это лучшие якоря для навигации по фильму.
- **`npm run cut --only` перезаписывал clips.json одними перерезанными битами**
  (починено мержем поверх прежнего манифеста). Если ролик вдруг собрался из двух
  клипов — проверь длину манифеста, а не композицию.
- **Длину бита задаёт `max(видео, озвучка)`.** Широкий диапазон в `script.ts`
  побеждает короткую реплику: 28 битов по 7–8 c дали 138 c вместо 60. Для битов
  с речью ставь `end = start + длительность озвучки + ~0.45 c` (длительности —
  в `public/vo/<Comp>/vo.json`), иначе ролик раздувается вдвое.
- **Индекс действий Gemini бесполезен на некоторых фильмах.** На «Годзилле и
  Конге» он описывал людей в джунглях и не замечал ни титанов, ни мини-Конга.
  Если две зоны подряд промахнулись — не трать на него время, переходи на
  обзорные контактные листы (шаг 20–25 c на весь фильм) и ищи глазами.

- **Контактный лист показывает кадр, а не границы плана.** Самая дорогая грабля
  «Стетхема»: 11 планов из 39 попали не туда. В диалоге, смонтированном
  «восьмёркой», план длится 1–2 c, и точка, где на листе с шагом 3 c сидит
  нужный герой, через секунду отдаёт собеседницу. Проверять надо **середину
  будущего клипа**, а не его начало. Лечится двумя приёмами: лист с шагом
  0.6–0.9 c по узкой зоне (видно, где план начинается и кончается) и правило
  «ищи непрерывный кусок» — в `StethamTales` все планы рассказчика взяты из
  одного 10-секундного дубля 982.5–992.5, где герой один в кадре.
- **Быстрый экшн промахивается ещё легче.** Кувырок или удар живут меньше
  секунды, и вырезка «по кадру с листа» отдаёт соседний план со стоящими
  людьми. Для кульминаций — лист с шагом 0.8–0.9 c, и берите момент ПЕРЕД
  пиком: клип должен начинаться на замахе, а не на точке удара.
- **Проверять готовые клипы дешевле, чем рендерить ролик.** Один кадр из
  середины каждого нарезанного клипа, склеенный в сетку через
  `ffmpeg -i "%02d.png" -filter_complex tile=5x8`, показывает весь монтаж за
  один взгляд и ловит промахи до рендера. (`drawtext` в Git Bash падает на
  fontconfig, `-pattern_type glob` не собран — нумеруйте кадры сами.)
- **Gemini размечает видео с точностью до секунды.** Кульминации (удар, падение,
  взрыв) промахиваются — точный кадр ищи контактным листом с шагом 0.3–0.5 c.
- **Gemini выдаёт перекрывающиеся диапазоны**: два разных плана с одним
  таймкодом. Кадр, который реально важен для сюжета, проверяй глазами.
- **ASR галлюцинирует на музыке**: подписи релизеров, «ПОДПИШИСЬ НА КАНАЛ».
  Стоп-лист уже в `index-quotes.ts`, но проверяй новые фильмы.
- **Дорожка 5.1 обязана сводиться в стерео при нарезке.** Речь в 5.1 живёт в
  центральном канале; клип с шестью каналами браузер в рендере микширует сам —
  тише и глуше (в готовом ролике было −22.6 LUFS вместо −15). `cut-clips` теперь
  отдаёт `-ac 2` до `loudnorm`, поэтому нормализация меряет то, что реально
  услышит зритель. Проверять — `ffmpeg -af ebur128`, цель ≈ −14 LUFS.
- **Слова на границе сегмента терялись у ASR.** Индекс относил слово к реплике,
  только если оно целиком внутри сегмента, а whisper регулярно выпускает
  последнее слово за его конец («Вы снизили» вместо «Вы снизили цену?»). Теперь
  слово относится по своей середине; для караоке по оригиналу это критично.
  Соседние сегменты при этом иногда перекрываются и отдают слово дважды —
  дубликаты отсекаются в `sourceWords`.
- **Кадр во весь экран двигается `object-position`, а не `transform`.** При
  `object-fit: cover` видео обрезано по контейнеру, поэтому сдвиг контейнера
  открывает чёрную полосу вместо соседней части кадра.
- **Персонажа нельзя резать краем — особенно говорящего.** Это требование
  заказчика и главная причина переделок. В вертикаль 9:16 от кадра 16:9 попадает
  ~32 % ширины, поэтому статичный сдвиг на бит не спасает: внутри бита меняется
  план и герой ходит по кадру. Окно должно ВЕСТИ персонажа — поле `pan`
  (`{ t, x }`, где `x` — доля ширины кадра) задаёт траекторию, точки вплотную по
  времени дают мгновенный переброс на склейке, вразбег — плавное сопровождение.
- **Границы планов внутри клипа берите детектором сцен**, а не на глаз:
  `ffmpeg -i clip.mp4 -vf "select='gt(scene,0.25)',showinfo" -f null -` печатает
  их с точностью до кадра, и переброс окна встаёт ровно на склейку.
- **Держите РОДНОЙ fps исходника.** Кино и сериалы идут в 23.976, а формат
  проекта — 30: приведение дублирует каждый пятый кадр, и на панорамировании
  это читается как микрофризы («аж блевать захотелось» — дословный отзыв).
  Сценарий экспортирует `export const FPS = 24000 / 1001`, `npm run cut` и
  композиция берут его. Проверка: `ffmpeg -i out.mp4 -vf mpdecimate -f null -`
  показывает уникальные кадры; было 1305 из 1594 (18 % дублей), стало 1218 из
  1271 (4 %), и остаток — дубли самого web-rip: в исходнике на статичном плане
  из 168 кадров уникальны 114.
- **Панорамируйте после апскейла, а не до.** Если кропать окно из нативных
  704×400, шаг движения равен пикселю исходника — почти пять пикселей экрана, и
  медленный проезд идёт ступеньками. Правильный порядок фильтров:
  `hqdn3d → scale до высоты 1920 → crop 1080×1920 по траектории → unsharp`.
  Масштабирование по-прежнему одно, а движение гладкое.
- **Где нет лица, там нет и автотрекинга.** Сцену, в которой герой согнут,
  отвернулся или снят со спины, детектор ведёт по посторонним (в «Кремниевой
  долине» окно уехало на велосипедиста, пока героя тошнило). Такой бит
  кадрируется вручную полем `pan` — это нормально, их единицы на ролик.
- **Позицию героя не определяйте «на глаз» по миниатюре.** Ошибка в 5 % ширины
  уже срезает лицо, а ручная разметка по контактным листам промахивается
  систематически. Ставьте `npm run track` (YuNet): он ведёт голову говорящего и
  сам находит склейки у краёв битов. `npm run pan` показывает результат
  контактным листом — секунды вместо минут рендера.
- **Говорящего выбирает разворот лица, а не его размер.** В сцене у врача
  Ричард сидел в профиль ближе к камере, врач стоял дальше анфас — по размеру
  побеждал Ричард, и говорящий не попадал в кадр вовсе. YuNet отдаёт пять точек
  лица; если нос стоит ровно между глазами, лицо повёрнуто к нам — это и есть
  говорящий в «восьмёрке».
- **Героя плана выбирайте по всему плану сразу, а не кадр за кадром.** Жадный
  выбор начинал сцену на одном человеке и уезжал к другому через пустую стену.
  Лица группируются в дорожки, дорожка с наибольшим весом ведётся весь план.
- **Вертикаль вырезайте в ffmpeg, а не в браузере.** Кроп поверх уже
  отмасштабированного клипа даёт двойной ресемплинг — на телефоне это видно как
  «пиксели». `crop` по траектории прямо из исходника + один `scale` lanczos +
  мягкий `unsharp` дают заметно более чистую картинку. Приближение (`zoom`) на
  рипе 704×400 не спасает дальний план, а только рушит качество: лучше
  выбрать другой кусок сцены.
- **Голос должен совпадать с лицом.** Женская реплика поверх мужского крупного
  плана ломает сцену — ищи в индексе подходящего персонажа.
- **Оригинальные диалоги мешают своей озвучке.** `cut-clips` вырезает полосу
  разборчивости (300–3400 Гц) в битах с репликами; в сценах без слов дорожка
  остаётся нетронутой — там она как раз работает.
- **Длину бита задаёт озвучка**, поэтому `vo` всегда до `cut`. Если фрагмент
  упирается в смену плана — короти текст, а не тяни видео.

## Кадрирование под вертикаль

Исходник шире 16:9 при вписывании занимает треть экрана. В `JuniorKumite`:
общий `videoScale` + `videoShiftY` в пропсах композиции (крутятся в студии),
плюс `zoom`/`panX`/`panY` на каждый бит в `script.ts`. Полосы сверху и снизу —
размытая копия кадра или чёрный (`bandStyle`), в них живут заголовок и караоке.

## Какие исходники просить

MKV вместо AVI; русские субтитры в раздаче (экономят шаг ASR); дорожка 5.1
(центральный канал = чистые диалоги, точнее ASR); 1080p без hardsub и логотипов
канала — вертикальный кроп режет по краям.

## Правовая рамка

Скажи один раз и по делу: у фильмов после 1950-х срок охраны не истёк,
площадки ловят их Content ID, а политика «inauthentic content» требует
трансформации (свой монтаж, свой текст, комментарий). Дальше решение
пользователя — работай по нему, не возвращайся к теме.

## Проверка

`npm run lint` → `npx remotion still` на стыках битов → `/qa-filmstrip`
(контактный лист + фризы) → отдельно послушать звук: не осталось ли оригинальных
голосов под репликами, не обрывается ли фраза склейкой.
