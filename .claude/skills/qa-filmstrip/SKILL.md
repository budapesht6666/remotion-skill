# QA Filmstrip

Агент **не может «смотреть» видео** — только читать статичные изображения. Поэтому
плавность проверяем двумя способами: (1) **контактный лист** — много кадров в
одной картинке, читаемой одним взглядом; (2) **детектор статтера** на ffmpeg —
числовой признак того, что какая-то анимация «утекла» мимо `useCurrentFrame()`.

`ffmpeg`/`ffprobe` уже есть в системе. Пути — под Windows/Bash-tool проекта.

## 1. Контактный лист из готового MP4 (быстро)

Тайлим каждый N-й кадр в одну картинку, потом **читаем её** (`Read` как image):

```bash
# 30-сек/60fps ролик: каждый 60-й кадр → 30 плиток → сетка 6×5
# -update 1 глушит варнинг image2 про паттерн имени при одиночном PNG.
ffmpeg -y -i out/<video>.mp4 -frames:v 1 -update 1 \
  -vf "select='not(mod(n,60))',scale=240:-1,tile=6x5" \
  out/_filmstrip.png
```

Правило сетки: `step` подбирай так, чтобы плиток вышло ~24–36
(`totalFrames / step ≈ ширина×высота`). Затем `Read out/_filmstrip.png` и оцени:
непрерывность движения камеры, равномерность easing'а, нет ли скачков/провалов,
как читается пейсинг сцен.

## 2. Контактный лист без полного рендера (из композиции)

Когда MP4 ещё нет — рендерим стиллы на выбранных кадрах и тайлим их:

```bash
mkdir -p out/_frames
for f in 0 120 300 480 720 900 1080 1260 1440 1560 1680 1770; do
  npx remotion still <CompId> "out/_frames/f$(printf '%04d' $f).png" --frame=$f
done
ffmpeg -y -pattern_type glob -i "out/_frames/f*.png" \
  -frames:v 1 -update 1 -vf "scale=240:-1,tile=6x2" out/_filmstrip.png
```

Дороже (каждый still — своя сборка+рендер), но не ждёт полного ролика. Кадры
подбирай по драматургии (границы сцен, пики движения).

## 3. Детектор статтера / дублей / фризов

Честно frame-driven анимация при 60fps даёт **все кадры разными**. Дубли/фризы —
красный флаг (CSS-transition, `setInterval`, `useFrame`, забытый `frame`).

```bash
# Сколько УНИКАЛЬНЫХ кадров осталось после отброса дублей (сравни с total):
# у честного 60fps-движения ≈ total; сильно меньше → статтер/низкий эфф. fps.
ffmpeg -i out/<video>.mp4 -vf mpdecimate -f null - 2>&1 \
  | grep -oE "frame=[ ]*[0-9]+" | tail -1

# Где именно подвисает (интервалы «заморозки», выводятся строками freeze_*):
ffmpeg -i out/<video>.mp4 -vf "freezedetect=n=-50dB:d=0.2" \
  -map 0:v:0 -f null - 2>&1 | grep -iE "freeze_(start|duration|end)"
```

Уникальных сильно < total или фризы в СЕРЕДИНЕ ролика → ищи анимацию не от
`useCurrentFrame()` (золотое правило №1). Фризы/дубли только в конце — это обычно
намеренный статичный холд (напр. финальная надпись на чёрном); сверяй с задумкой.
Пример с MatrixRain: 1726/1800 уникальных, freezedetect молчит до 27.2 c —
анимационная часть чистая, «дубли» это холд надписи.

## 4. Мелочи для проверки

```bash
# Базовые метаданные (кодек/размер/fps/длительность/кадры):
ffprobe -v error -select_streams v:0 \
  -show_entries stream=codec_name,width,height,r_frame_rate,nb_frames,duration \
  -of default=noprint_wrappers=1 out/<video>.mp4

# Лёгкое GIF-превью сегмента для быстрого шэра (не для покадрового анализа):
ffmpeg -y -ss 8 -t 4 -i out/<video>.mp4 \
  -vf "fps=15,scale=360:-1:flags=lanczos" out/_preview.gif
```

## Итог
После сборки/правок: собери `_filmstrip.png` → прочитай его → прогони детектор
статтера. Отчитывайся честно: если нашлись фризы/дубли — покажи вывод, а не
«всё плавно». Временные файлы (`out/_frames`, `out/_filmstrip.png`,
`out/_preview.gif`) — служебные, в финальную выдачу не идут.
