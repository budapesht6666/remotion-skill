# Whiteboard

Доска, на которой рука с маркером рисует контент под закадровый монолог.
Эталон — композиция `Whiteboard`, референсы — `docs/reference/`.

Ключевая идея: **растр нельзя «нарисовать пером»**, `stroke-dasharray` работает
только по обводке SVG. Поэтому картинка проявляется через анимированную маску,
штрихи которой обводят её собственные контуры (их даёт potrace), и по тем же
контурам едет рука. Всё на доске — иллюстрация, надпись, акцент — сводится к
одному примитиву: штриху со своим окном кадров.

**Стилей рисунка два**, и они противоположны по требованиям к трассировщику.
`line` (дефолт) — плоский контурный line-art: обвели контуры, открылось всё.
`graphite` — реалистичный карандаш с тоном и растушёвкой; там обводка одна
картинку не откроет, и рисование идёт в ДВЕ ФАЗЫ. Подробности ниже, эталон —
`MoonStrike`.

## Пайплайн

```bash
npm run art   -- --hand              # рука с маркером: генерация → вырезание фона → поиск кончика
npm run art   -- --hand --pencil     # рука с карандашом — под стиль graphite
npm run art   -- --glove             # мультяшная перчатка-курсор для kind: "click"
npm run art   -- <Композиция>        # иллюстрации по BOARD: генерация + трассировка → art.json
npm run vo    -- <Композиция>        # озвучка фраз SCRIPT (ElevenLabs → Gemini → edge-tts)
npm run board -- <Композиция>        # раскладка, бюджет кадров, камера, валидация → board.json
npx remotion render <Композиция> out/<Композиция>/demo.mp4 --bundle-cache=false
```

Флаги: `--trace` (не генерить, только трассировать), `--force` (перегенерить),
`--only id1,id2` (точечно), `--dry` у `board` (раскладка без ffmpeg, секунды),
`--silent` у `board` (без озвучки, тайминги по `--seconds`).

`npm run board` **обязателен после каждого** `npm run vo`: длительности фраз
меняются, и вся раскладка едет за ними.

## Что пишет автор — `script.ts`

Два массива. `SCRIPT: Phrase[]` — фразы монолога (формат общий с `npm run vo`).
`BOARD: BoardItem[]` — элементы доски, каждый привязан к фразе полем `line` и
делит её длительность с соседями по весам.

| Тип | Поля | Зачем |
|---|---|---|
| `art` | `subject`, `rect`, `aspect?`, `style?`, `backdrop?`, `accent?`, `shadeShare?` | Иллюстрация. `subject` — только сюжет, стиль подставляет `gen-image.ts` |
| `text` | `text`, `x`, `y`, `size?`, `font?`, `align?` | Надпись. Переносы только вручную через `\n` |
| `accent` | `target`, `style`, `padding?`, `seed?` | Обводка/подчёркивание/рамка вокруг другого элемента |
| `click` | `target`, `sfx?` | Мультяшная перчатка прилетает и жмёт по уже нарисованному (концовка «жми на колокольчик») |

Общее у всех: `screen` (номер экрана, камера прокручивается сама), `weight`
(доля бюджета фразы), `hold` (выдержка в хвосте слота), `note`.

**`rect` — прямоугольник ЧЕРНИЛ внутри экрана, а не холста картинки.** Генератор
всегда оставляет широкие поля; посадка идёт по чернилам (`fitInkToBox`), иначе
объект выходит вдвое мельче задуманного и кадр выглядит пустым.

## Графит: две фазы рисования

`style: "graphite"` даёт реалистичный карандашный рисунок — тон, растушёвка,
полный диапазон от белой бумаги до почти чёрного. Обводка контуров такую
картинку не откроет: тон лежит по площади, а не вдоль линий. Поэтому:

```
фаза 1  ОБВОДКА     узкое перо по контурам potrace   (главные формы)
фаза 2  РАСТУШЁВКА  широкое перо серпантином по площади рисунка
```

Обе фазы — те же `Stroke` со своим окном кадров, поэтому инвариант «активный
штрих в кадре ровно один» держится. Регистрация слоёв не нужна: и контуры, и
серпантин считаются из ОДНОГО растра. Бюджет делится полем `shadeShare`
(дефолт 0.55), между полосами растушёвки отрыва пера нет — карандаш ходит
туда-сюда, не отрываясь.

| Поле | Что делает |
|---|---|
| `backdrop: "dark"` | Фон залит графитом до краёв кадра. На белой доске получается тёмное окно; рука закрашивает его штриховкой |
| `backdrop: "paper"` | Объект на чистой бумаге (дефолт) |
| `accent` | Единственное цветное пятно, обычной фразой: «the impact flash, in hot orange». Остальное графитное |
| `shadeShare` | Доля бюджета кадров на растушёвку |

Что важно знать про механику:

1. **Полярность трассировки зависит от фона.** На залитом фоне объект СВЕТЛЫЙ,
   и потрейс запускается инвертированным (`light-on-dark`). Иначе он обведёт не
   Луну, а виньетку по краю кадра.
2. **Порог адаптивный** — перцентиль гистограммы (22% самых тёмных или самых
   светлых). Абсолютный порог не годится: у рисунка на бумаге тёмное это 10%
   площади, у рисунка с залитым фоном — 70%.
3. **Уровень бумаги снимается с углов кадра.** Константа 242 объявляла
   содержимым весь кадр (генератор отдаёт «белую бумагу» кремовой и с зерном),
   и рисунок садился в рамку вдвое мельче, а рука растушёвывала пустые поля.
   У `backdrop: "dark"` вопроса нет: содержимое — весь кадр.
4. **Контуров берётся только несколько самых длинных** (`OUTLINE_MAX = 10`).
   Отбрасывать мелочь безопасно: недостающее закроет растушёвка, а по
   завершении элемента маска снимается совсем (`revealAll`).
5. **Растушёвка идёт только по фактическому размаху рисунка в полосе** (скан
   пикселей), пустые полосы пропускаются, направление чередуется. Без этого
   рука возит пером по чистой бумаге и это сразу видно.

## Концовка с кликом по колокольчику

`kind: "click"` — единственный элемент доски, который НЕ рисуется пером.
Перчатка (`npm run art -- --glove`) прилетает снизу на готовый кадр, жмёт по
цели, цель качается, играет звон (`public/sfx/bell.mp3`, синтезируется ffmpeg).
Своих координат у клика нет: точка нажатия берётся из бокса цели, поэтому
элемент-цель должен быть нарисован раньше.

В манифесте клики лежат отдельным полем `clicks`, а не в `elements`: у них нет
штрихов, и логика поиска активного штриха считала бы их пустым элементом.
Кончик пальца у перчатки ищется как самая ВЕРХНЯЯ тёмная точка (`tip: "top"`) —
палец поднят вверх, в отличие от маркера и карандаша.

Подлёт длинный нарочно (26 кадров): рисующая рука уходит за 22 кадра после
последнего штриха, и нажатие должно случиться уже без неё — иначе в кадре
одновременно две руки.

## Грабли (каждая стоила итерации)

1. **`@remotion/paths` не кэширует ничего.** Каждый вызов `getLength` /
   `getPointAtLength` / `evolvePath` заново парсит и семплирует весь путь.
   Держи инвариант: длины считаются в Node и лежат в манифесте; не начатые
   штрихи не рендерятся; дорисованные — обычный `<path d>` без dash-атрибутов;
   активный штрих в кадре ровно один (компилятор это проверяет). Итого ≤3
   вызова API на кадр **независимо от числа контуров**.
2. **Сплошные фигуры надо заливать, а не только обводить.** Контур залитой
   стрелки, обведённый пером в 20 единиц, откроет кромку, а середина останется
   скрытой. `traceArtwork` помечает такие контуры `solid` (проба яркости в
   центре бокса), и в маске они после обводки заливаются.
3. **Богатая картинка даёт 30+ контуров** — на четырёхсекундной фразе это по два
   кадра на штрих, рисунок «проявляется рябью». `mergeContours` сливает мелкие
   соседей, потолок `MAX_CONTOURS = 16`.
4. **Пол в кадрах на штрих переполнял слот.** Наивное «максимум из веса и пола»
   давало 93 кадра там, где слот 90, элементы наезжали друг на друга и ломался
   инвариант из п.1. Пол раздаётся всем сразу, по весам делится только остаток.
5. **Фон руки режется заливкой от границ, а не порогом яркости.** У генерации фон
   с виньеткой, и абсолютный порог оставлял вокруг кисти светлый прямоугольник —
   на бумаге он отчётливо виден.
6. **Рука не должна замирать.** Пока она парковалась в паузах между штрихами,
   четверть ролика была дублями кадров. Перелёт по дуге между концом одного
   штриха и началом следующего убрал 240 дублей из 283.
7. **Частота и размах подёргивания кисти — свойства РУКИ, а не текста.** Период
   в кадрах (`handWobbleFrames`), размах в пикселях доски (`handWobbleAmp`),
   траектория — эллипс, а не вертикаль. Первая версия считала фазу от числа
   букв, а размах от кегля: одна и та же рука дёргалась на «O₂ ×30» вдвое
   медленнее, чем на «чувствует спиной». Скорость появления текста при этом
   отдельный параметр — её задаёт бюджет кадров штриха, то есть длительность
   фразы.

   **Размах подбирай замером, а не на глаз.** Скорость пера считается из
   манифеста: `сумма(length × scale) / сумма(frames)` по элементу. Ориентир из
   демо — на иллюстрациях перо идёт **150–275 px/кадр**, а текст своим ходом
   ползёт **4–8**: разницу в 30–60 раз глаз ловит мгновенно, и именно она
   читается как «текст пишется неправильно». Размах в 4 px не менял ничего —
   его не видно на кадре 1080 px.

   Путь пера за цикл — периметр эллипса `amp × 0.45·amp`, скорость — этот
   периметр делить на период плюс собственный ход строки. Принятые в демо
   **7 кадров / 15 px** дают ~14 px/кадр: рука заметно работает, но не
   размахивает. Полностью догонять рисунок не надо — для 275 px/кадр
   понадобился бы размах 190 px, и кисть летала бы через треть экрана.

   Проверять **только на полном кадре**. На увеличенном кропе движение в
   несколько пикселей выглядит убедительно, а в ролике его нет.
8. **Текст на доске — печатный, не рукописный.** Он открывается протяжкой, то
   есть рука его ЗАКРАШИВАЕТ. Рукописный шрифт обещает письмо по буквам,
   которого протяжка дать не может, и читается подделкой. Одноштриховой
   кириллицы, которой можно было бы писать по-настоящему, в свободных шрифтах
   только плоттерный serif; русской прописи нет вообще.
9. **Ширина строки в манифесте — оценка** (метрик шрифта в Node нет). Клип
   считается браузером по `width: max-content`, иначе длинное слово обрезается:
   «РЫБА» превращалась в «РЫБ». Оценка нужна только для позиции руки.
10. **Safe-area проверяется по чернилам**, а не по холсту картинки и не по боксу
   акцента — иначе валидатор ругается на каждый элемент.
11. **Авто-дубляж YouTube переводит только звук.** Нарисованное на доске
    останется на языке оригинала поверх чужой озвучки. Держи надписи в 1–3
    слова, приоритет цифрам и символам (`O₂ ×30`, `−40°`), смысл несёт голос.
12. **`MAX_CONTOURS = 16` — цель, а не гарантия.** `mergeContours` сливает
    только МЕЛКИХ СОСЕДЕЙ: если контуры крупные или разбросаны, дожать до 16 он
    не может. Живой замер: 257 контуров слились всего до 87 при бюджете 98
    кадров — 1.1 кадра на контур, то есть картинка вспыхивает кусками вместо
    рисования. Лечится **только упрощением сюжета**, и валидатор именно это и
    советует. Контуры плодят три вещи, и все три не несут смысла: **текстура
    поверхности** (волнистый грунт — 257 → 20 после «no ground texture»),
    **пунктир** (каждый штрих = контур: 113 → 10 после «one single solid
    curved line») и **мелкие детали конструкции** (стойки, перекладины трапа,
    колёса — 148 → 20 после «no ladders, no struts, no wheels»). Проверять
    сразу после `npm run art`: если у картинки больше ~40 контуров, она уже не
    нарисуется честно.
13. **Генератор кадрирует впритык.** «Generous white margin» в стилевом промпте
    он игнорирует: солнце уезжало за край кадра. Если картинка должна быть
    целиком в поле, это пишется в `subject` явно — «everything sits fully
    inside the frame with a wide empty margin, nothing touches the edges».
14. **`npm run art -- <Комп> --only a,b` ПЕРЕЗАПИСЫВАЕТ `art.json` только
    выбранными.** Остальные записи пропадают, и следующий `npm run board`
    ругается «нет в art.json» на картинки, PNG которых лежат на месте.
    Лечится `npm run art -- <Комп> --trace` — он бесплатно перетрассирует все
    PNG с диска. Гоняй `--trace` после каждого `--only`.
15. **`gemini-2.5-flash-image` регулярно отвечает «high demand».** Это не квота
    и не биллинг, ретрай той же моделью не помогает; выручает
    `--model gemini-3.1-flash-image`. Ошибка валит процесс с
    `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)` — это шумное
    падение node на выходе, а не отдельная проблема.
16. **Светлая кромка вокруг залитого фона переживает обрезку и становится
    контуром.** Промпт прямо просит бликовать графитом до краёв, генератор всё
    равно оставляет полоску. `trimLightBorder` срезает ряды, где светлого
    подавляющее большинство, но лоскут вдоль ОДНОЙ стороны так не ловится: в
    кадре он открывал кусок фона в углу картинки, будто там что-то нарисовано.
    Добивается фильтром краевых артефактов — контур, прилипший к кромке и
    мелкий относительно главного (порог по ПЛОЩАДИ: по толщине не ловилось,
    лоскут был 56×270 на холсте 1024).
17. **Пустая фраза без элементов = замершая доска.** Рука в паузе летит к
    следующему элементу, но на большом кадре её движение — единственное, что
    меняется, и `freezedetect` честно называет это фризом. Две пустые фразы
    подряд дали **8.4 секунды** статики в середине ролика (2279 уникальных
    кадров из 2710). Правило: подряд пустых фраз не больше одной, а если фраза
    длинная — вешать на неё хотя бы акцент. Дёшево это делается сдвигом
    акцента на следующую фразу: подчёркивание рисуется отдельно от надписи.
18. **У графита на бумаге холст надо резать и обесцвечивать в альфу.** Лист
    генератора кремовый и заметно больше рисунка: на доске он ложился ВИДИМЫМ
    прямоугольником, закрывал соседнюю надпись, а при качании от клика
    поворачивался целиком. Лечится парой `cropToContent` + `keyPaperToAlpha`.
    Резать при этом надо ПО СОДЕРЖИМОМУ, а не отшелушивая светлые ряды с краю
    (`trimLightBorder`): генератор кладёт по кромке лёгкую виньетку, одного
    такого ряда хватает, чтобы отшелушивание не началось вовсе. Для залитого
    фона наоборот — годится только отшелушивание, там «поля» это светлая кайма.
19. **`greyscale().raw()` у картинки с альфой отдаёт ДВА канала на пиксель.**
    После `keyPaperToAlpha` все рисунки на бумаге стали RGBA, и сканы вида
    `data[y * width + x]` начали читать мусор. Ошибки при этом нет — просто
    обрезка полей молча перестаёт срабатывать. Поэтому `readGrey` сводит
    картинку на белый (`flatten`) перед чтением; заодно это делает пайплайн
    идемпотентным — прозрачная бумага читается как белая.
20. **Рука обрывается прямым срезом там, где кончается её PNG.** Предплечье
    уходит за границу картинки, и на белом листе это читается как обрезанная
    фотография. Лечится в `cutoutHand` затуханием альфы по кромке кадра
    (`EDGE_FADE`), а не подгонкой `handWidth`: размер лишь двигает срез.
    Плюс генератор охотно дорисовывает под грифелем «уже нарисованные» штрихи —
    они потом ездят с рукой по всей доске, и запрет на них стоит в промпте
    отдельной строкой.

## Один рецепт — много роликов

Композиция `Whiteboard` не единственная: путь к манифесту задаётся пропом
`boardFile` (`"clips/<Комп>/board.json"`), а компонент, `schema.ts`, `types.ts`
и все скрипты пайплайна общие. Чтобы завести новый ролик на доске, хватает
`src/compositions/<Комп>/{script.ts, voices.ts}` и регистрации `<Composition/>`
с `component={Whiteboard}` и своим `boardFile`. Эталоны: `MoonScar`
(англоязычный контурный, по новостному тренду) и `MoonStrike` (реалистичный
графит с растушёвкой и карандашной рукой).

**Переезд на другой язык** — ровно две правки в `voices.ts`: `edgeVoice` (в
эталоне зашит `ru-RU-DmitryNeural`) и `stylePrompt` для Gemini. Шрифты в
`src/lib/fonts.ts` грузят и латиницу, и кириллицу, модель ElevenLabs
`eleven_multilingual_v2` язык не различает. Помни только, что `ADVANCE` в
компиляторе калибровался по кириллическому капсу и на латинице слегка
завышает ширину строки — это сдвигает руку, но не текст.

## Настройка руки в студии

Параметры руки крутятся в правой панели `npm run dev` без перерендера. Чтобы
панель вообще появилась, у композиции есть Zod-схема (`schema.ts`), а
`defaultProps` — **строго литералы**.

Панель молча исчезает, если в `defaultProps` попадёт хоть одно из этого:
приведение типа (`as string | null`), ссылка на константу (`FORMAT.width`),
арифметика или спред объекта. Ошибки при этом не будет — просто пустой
инспектор, и найти причину глазами невозможно. Отсюда же правило: **пути
хранятся пустой строкой вместо `null`** (`handSrc: ""` → векторный маркер,
`musicSrc: ""` → без музыки), потому что nullable-поля студия показывает плохо.
