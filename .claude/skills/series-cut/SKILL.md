# Series Cut

Пайплайн «чужой сериал → вертикальный шортс на 40–55 c», в котором **ничего не
переозвучивается**: звучат оригинальные голоса, а работа идёт в трёх местах —
выбор сцены, точность границ битов и кадрирование под вертикаль.

Эталон — композиция `ValleyAuction` («Кремниевая долина» s01e01: торги за
стартап). Родственный рецепт `/film-remix` — про НАШУ озвучку поверх чужих
кадров (смешной перевод, закадровый монолог); если герои должны говорить своими
голосами, идите туда.

## Чем этот рецепт отличается

| | `/film-remix` | `series-cut` |
|---|---|---|
| Звук | наша озвучка, оригинал приглушён | только оригинал |
| Субтитры | по таймингам TTS | по словам ASR-индекса (`subs: "source"`) |
| Липсинк | не совпадает | совпадает всегда |
| Главная работа | текст и подбор кадров под него | выбор сцены и кадрирование |

## Шаг 0. Выбрать сцену — по популярности, а не по вкусу

Прежде чем открывать индекс реплик, **поищите в интернете**, какие сцены
зрители называют лучшими: `WebSearch` по запросам вида
«<сериал> best funniest scenes ranked», «most rewatched moments», подборки
WatchMojo / Looper / Ranker, обсуждения на Reddit. Это дёшево и меняет выбор
материала: у «Кремниевой долины» в топ-10 WatchMojo попали сразу два эпизода из
первой же серии, включая «Panic Attack Diagnosis», который и стал концовкой
ролика.

Сцена годится в шортс, если выполняются три условия:

1. **Понятна без контекста.** Зритель не смотрел сериал: «два инвестора
   торгуются за парня» читается сразу, «Гилфойл шутит про Джареда» — нет.
2. **Есть нарастание и панч.** Ставка растёт, герою всё хуже, финальная реплика
   переворачивает смысл. Компиляция «лучших моментов» проигрывает одной сцене:
   она меняет контекст каждые несколько секунд и теряет зрителя на склейках.
3. **Держится на речи, а не на визуале.** В вертикали видно треть кадра —
   зрелище с широкой мизансценой развалится, диалог крупными планами нет.

Драматургия ролика (проверена на `ValleyAuction`): крючок первой репликой →
рост → слом → цена → панч в последнем кадре. Никаких титров, плашек и
пояснений поверх кадра — их пользователь не просил, а они съедают лицо и
воспринимаются как реклама. Единственное исключение — кнопка Subscribe в
хвосте за панчем (см. «Концовка»).

## Пайплайн

```bash
npm run subs   -- <фильм>                 # индекс реплик из субтитров (бесплатно, точнее)
npm run quotes -- <фильм>                 # если субтитров в контейнере нет — ASR через Groq
npm run sheet  -- <фильм> --from 20:29 --to 20:41 --every 0.6   # смотрим сцену глазами
# → пишем src/compositions/<Comp>/script.ts
npm run track  -- <Comp>                  # трекинг лиц → траектории окна + склейки у краёв
npm run cut    -- <Comp>                  # вырезка вертикали + субтитры из индекса
npm run pan    -- <Comp>                  # контактные листы клипов: проверка кадрирования
npx remotion render <Comp> out/<Comp>/<имя>-v1.mp4   # версионно: см. «Файлы и версии»
npm run joins  -- <Comp>                  # стыки: не мелькает ли на склейке чужой кадр
```

Проверка перед сдачей — `/qa-filmstrip` плюс обязательно:

```bash
ffmpeg -i out/<...>.mp4 -vf mpdecimate -f null -   # уникальных кадров ≈ всем
ffmpeg -i out/<...>.mp4 -af ebur128 -f null -      # −14 LUFS
```

## Инструмент: трекинг лиц (YuNet)

Ставится один раз:

```bash
pip install opencv-python
curl -sL -o data/models/face_detection_yunet.onnx \
  https://github.com/opencv/opencv_zoo/raw/main/models/face_detection_yunet/face_detection_yunet_2023mar.onnx
```

`npm run track` (scripts/track-faces.ts + scripts/lib/face_track.py) для каждого
бита: находит границы планов детектором сцен ffmpeg, прогоняет YuNet по кадрам,
выбирает героя и пишет траекторию окна в `data/track/<Comp>.json`. `npm run cut`
читает её и вырезает вертикаль.

Два правила выбора героя, без которых всё ломается:

- **Говорящего определяет разворот лица, а не размер.** YuNet отдаёт пять точек
  (глаза, нос, углы рта); если нос стоит между глазами, лицо повёрнуто к нам. В
  «восьмёрке» к камере повёрнут говорящий, собеседник стоит в профиль или
  затылком — и по размеру он часто крупнее, потому что ближе.
- **Герой выбирается сразу по всему плану.** Лица группируются в дорожки, у
  дорожки суммарный вес, победитель ведётся всю сцену. Выбор кадр за кадром
  начинает план на одном человеке и уезжает ко второму через пустую стену.

Ручные рычаги в `script.ts`, когда автоматика не справляется:
`follow: 0.55` — подсказка «нужный герой примерно здесь по ширине»;
`pan: [{ t, x }]` — полная ручная траектория (доли ширины кадра).

## Инструмент: проверка стыков (`npm run joins`)

```bash
npm run joins -- <Comp>                                   # берёт свежий рендер из out/<Comp>/
npm run joins -- <Comp> --video out/<Comp>/<имя>-v2.mp4   # или конкретный файл
```

Предупреждений `npm run track` **недостаточно**: они считаются по таймкодам
исходника ДО нарезки, а границы после этого двигают, биты перерезают `--only`,
и лишний кадр появляется там, где предупреждения не было. `npm run joins`
смотрит на то, что реально увидит зритель:

- меряет в каждом нарезанном клипе, далеко ли ближайшая смена плана от его
  краёв, и ругается, если обрывок короче 0.35 c (порог `MIN_SHOT`);
- собирает лист `out/<Comp>/joins/joins.png`: строка = один стык, слева кадры
  конца бита, справа начала следующего. **Лист надо прочитать глазами** — числа
  не отличают осмысленный кадр реакции от мусора;
- собирает лист на каждый бит (`out/<Comp>/joins/<id>.png`) по склейкам ВНУТРИ
  него: строка = склейка оригинального монтажа, слева последний кадр старого
  плана, дальше три первых кадра нового. Три кадра нового плана обязаны быть
  кадрированы одинаково; если первый выбивается — это баг переброса окна, а не
  монтаж. Проверять надо каждый бит: брак кропа появляется на всех склейках
  сразу, но глаз цепляется только там, где планы меняются часто;
- если клипы перерезали после рендера, лист не собирается: скрипт сравнивает
  сумму кадров манифеста с кадрами файла и говорит, что рендер устарел. Цифры по
  клипам при этом верны, поэтому командой можно пользоваться и до рендера.

## Кадрирование: жёсткие правила

- **Персонажа нельзя резать краем, говорящего — тем более.** Это первое, что
  замечает зритель, и первое, за что заказчик заворачивает работу.
- **Голова говорящего держится в центре окна** всю длину бита. Камера в ситкоме
  едет, планы живут 1–2 секунды — статичный сдвиг на бит не спасает.
- **Не увеличивать.** `zoom` выше 1 на рипе 704×400 сразу читается пикселями.
  Дальний план не спасает приближение — берите другой кусок сцены.
- **Порядок фильтров:** `hqdn3d → scale до высоты 1920 → crop 1080×1920 по
  траектории → unsharp`. Кроп ДО апскейла даёт ступеньки: шаг окна равен пикселю
  исходника, то есть почти пяти пикселям экрана.
- **Родной fps исходника.** Кино идёт в 23.976; приведение к 30 дублирует каждый
  пятый кадр, и на движущемся окне это микрофризы. Сценарий экспортирует
  `export const FPS = 24000 / 1001`, композиция и нарезка берут его.

## Субтитры

Строятся автоматически по словам индекса (`subs: "source"` у бита): звучит
оригинал, караоке подсвечивает слово, которое произносится. Мат остаётся в
звуке (он держит интонацию) и маскируется в тексте — `maskProfanity`,
«Ё*****-воробушки». Плашка под текстом обязательна: кадры сериала пёстрые,
обводка на них не спасает. Держите субтитр выше нижних ~20 % экрана — их
перекрывает интерфейс площадок.

## Грабли (каждая стоила итерации и правки)

- **`--only` не должен затирать общий файл.** `npm run track --only a08`
  перезаписал `data/track/<Comp>.json` одним битом, следующая полная нарезка не
  нашла траекторий и молча поставила окно по центру у всех — лица уехали за край.
  Ровно та же грабля была раньше у `npm run cut --only` с `clips.json`. Оба
  скрипта теперь мержат поверх прежнего файла, а `cut` падает, если у бита нет
  траектории. **Проверяйте состав файла после `--only`.**
- **Смена плана у самого края бита = «лишние кадры».** Бит открывается или
  закрывается чужим кадром, на монтаже это выглядит как мусор. `npm run track`
  предупреждает и называет, куда сдвинуть границу.
- **Где нет лица — нет и автотрекинга.** Герой согнут над урной, снят со спины,
  далеко — детектор ведёт прохожих (у нас окно уехало на велосипедиста). Такие
  биты кадрируются вручную через `pan`; их единицы на ролик.
- **Дорожка 5.1 сводится в стерео при нарезке** (`-ac 2` до `loudnorm`): речь
  живёт в центральном канале, иначе браузер микширует сам и тише на 8 dB.
- **ASR теряет слово на границе сегмента** («Вы снизили» вместо «Вы снизили
  цену?») — в `index-quotes` слово относится к реплике по своей середине, дубли
  из перекрытий отсекаются.
- **«Мигание» на склейках — это кроп, а не монтаж.** Самая дорогая ошибка
  рецепта: на каждой смене плана один кадр оказывался кадрирован «между» двумя
  планами — голова у края, полкадра стены. Причина не в границах битов, а в
  траектории окна: смена плана записана парой точек с зазором 0.01 c, и
  `panExpression` их ИНТЕРПОЛИРОВАЛ, поэтому кадр, попавший в зазор, получал
  промежуточное положение окна. Плюс время склейки в треке округлено до сотых,
  и первый кадр нового плана иногда доставался старому окну. Лечится в
  `scripts/cut-clips.ts`: пара точек короче полутора кадров считается
  ступенькой (никакой интерполяции), а порог сдвинут на полкадра назад.
  **Признак в кадре:** первый кадр после склейки кадрирован иначе, чем
  следующие два. Заметнее всего в частой восьмёрке — там склейка каждые
  полсекунды, и брак читается как мигание, хотя каждый отдельный кадр «просто
  чуть сдвинут». Смотреть надо `npm run joins` (листы по битам), а не общий
  контактный лист: у него шаг в десятки кадров, и такой кадр в него не попадает.
- **Ошибка ASR уезжает прямо в субтитр.** При `subs: "source"` текст на экране —
  это `quotes.json`, а не то, что слышно. `whisper-large-v3-turbo` на быстрой
  речи сочиняет («скончай мячиськи» вместо «кончай мять сиськи»). Прочитайте
  выбранные реплики глазами и сомнительные переспросите старшей моделью
  (`whisper-large-v3`) на вырезанном фрагменте: 10 секунд аудио — секунды
  работы. Правка идёт пословно в `quotes.json` (и заодно в `quotes.txt`):
  караоке живёт по `words`, а не по `text`.
- **Чужой кадр на склейке видно даже в один кадр.** Соблазн «оставить как есть,
  там же полтора кадра» — ошибка, проверенная на живом ролике: заказчик увидел
  мелькание и на 2 кадрах, и на 3. Но и сдвиг «как советует трекер» бывает
  нельзя: точка склейки часто приходится на последнее слово реплики, и подрезка
  обрубает его в звуке. Тогда границу двигают В ДРУГУЮ сторону — **отпускают
  вперёд**, чтобы новому плану хватило времени прочитаться как кадру реакции
  (от ~0.35 c, то есть 8–10 кадров). Дальше начала следующей реплики отпускать
  нельзя: она оборвётся на полуслове. Итого выбор всегда из двух: подтянуть ДО
  склейки или отпустить ЗА неё — «немножко чужого кадра» не бывает.
- **Первый кадр ролика проверяйте отдельно.** Обрывок предыдущего плана в начале
  первого бита `npm run track` не поймал ни разу: он мал (1 кадр), а стыка перед
  ним нет. Это худшее место для мусора — именно этот кадр показывают в ленте.
  `npm run joins` меряет и голову первого клипа тоже.
- **План без лица правится куском траектории, а не всем битом.** Герой,
  снятый со спины, уводит детектор на мебель, но остальные девять планов бита
  трекер ведёт верно. Возьмите траекторию из `data/track/<Comp>.json`, замените
  участок этого плана и положите результат в `pan` бита (`beat.pan` перекрывает
  трек целиком, поэтому копируется вся траектория, а не разница).
- **Проверять кадрирование листами, а не рендером.** `npm run pan` собирает
  контактные листы клипов за секунды; рендер — минуты. Смотреть надо каждый бит,
  а не выборочно.
- **Не додумывать оформление.** Титульные плашки, финальные карточки, «а давайте
  ещё заголовок» — если пользователь не просил, этого в ролике быть не должно.

## Концовка: кнопка Subscribe

Внутри сцены призыву подписаться места нет — последняя реплика в хорошо
отобранном материале договаривает буквально до последнего кадра, и плашка
поверх панча его убивает. Поэтому концовка живёт **хвостом за монтажом**:
проп `outroFrames` компонента (60 кадров ≈ 2.5 c на 23.976 fps; `0` — без
концовки, длину хвоста добавляет `calculateMetadata`).

Как устроено (`OutroFreeze` + `SubscribeCta`):

- **Стоп-кадр без файла.** Последний кадр держит `<Freeze frame={длина клипа −
  1}>` вокруг того же `<OffthreadVideo>` — отдельную картинку в `public/`
  вырезать не нужно. Стык бесшовный: первый кадр хвоста совпадает с последним
  кадром клипа.
- **Стоп-кадр обязан двигаться.** Замерший кадр в ленте читается как зависшее
  видео, поэтому кадр медленно наезжает (+2 % в секунду) и темнеет до ~50 % —
  движение остаётся, внимание уходит на кнопку. Анимацию считаем **снаружи**
  `<Freeze>`: внутри него `useCurrentFrame()` заморожен вместе с картинкой.
- **Блок общий для всех роликов** — `src/components/SubscribeOutro.tsx`
  (наезд, затемнение, кнопка) поверх вашего фона; длину хвоста берите из
  `subscribeOutroFrames(fps)`. Кнопка нарисована в SVG/CSS, ассетов не требует
  и работает на любом fps. Курсор-рука жмёт **нижнюю кромку** кнопки — палец
  поверх надписи закрывает буквы. Звон — `sfx/subscribe-bell.mp3` (настоящая
  запись колокольчика, CC0; синтезированный `sfx/bell.mp3` слышен как «пиип»).
  Подробности и правила — в `/shorts-director`, раздел «Кнопка Subscribe».

`freezedetect` на таком ролике честно найдёт фриз в хвосте — это ожидаемо,
проверяем только участок до конца последнего клипа.

## Файлы и версии

Рендер всегда идёт в **новое имя с номером версии**:
`out/<Comp>/<имя>-v1.mp4`, `-v2.mp4`, … Предыдущий файл не трогаем и не
перезаписываем: сравнить «стало лучше или хуже» иначе нечем, а откатиться
некуда. Именно на этом обжёгся первый прогон — версию, которую заказчик хотел
вернуть, было уже не достать, каждый рендер писался в один и тот же путь.

Пережатых копий «для просмотра» не делаем: пользователю нужен путь к оригиналу.
(Лимит на отправку файла в чат — 30 МиБ, рендер обычно тяжелее; в этом случае
просто называем путь, а не плодим второй файл.)

## Чек-лист приёмки

1. `npm run pan` — во всех битах говорящий в кадре целиком, голова к центру.
2. `npm run joins` — предупреждений нет И листы прочитаны глазами: на стыках
   битов либо новый план сразу «свой», либо осмысленный кадр реакции, а не
   обрывок; на склейках внутри битов три первых кадра нового плана кадрированы
   одинаково. Отдельно смотрим первый кадр ролика.
3. `mpdecimate` — уникальных кадров ≈ всего (остаток 3–5 % — дубли самого рипа).
4. `freezedetect` — фризы только там, где актёр реально стоит неподвижно.
5. `ebur128` — около −14 LUFS, пик не выше −1 dBFS.
6. Первая секунда читается без звука; последний кадр сцены — панч (после
   него допустима только концовка с кнопкой Subscribe, см. раздел выше).
7. `npm run lint`.

## Правовая рамка

Сказать один раз и по делу: сериал под охраной, Content ID его ловит, а политика
«inauthentic content» требует трансформации (свой монтаж, свои субтитры). Дальше
решение пользователя — работайте по нему и к теме не возвращайтесь.
